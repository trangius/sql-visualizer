          pk
Primary key. An explicit pk wins over Id.

          null
Column may be NULL (default is NOT NULL).

          unique
UNIQUE constraint — this is how 1‑1 is made.

          auto_increment
The database numbers the rows itself. An integer Id gets this on its own; write it for another integer primary key. a_i for short.

          pk (A, B)
One primary key over several columns: only the combination must be unique, each column alone may repeat.

          unique (A, B)
The combination is unique. Here: one dog per place at each show.

          index
An index on the column, so searches and JOINs on it are fast. index (A, B) for one over several columns.

          -> Table
Foreign key to that table's primary key. The column inherits its type.

          -> T.Col
Foreign key to a specific (PK or unique) column. MariaDB also takes one an index starts with.

          [delete cascade]
Last on a -> line: deleting the row it points to deletes this row too. [delete set null] empties the column instead (it must be null); [update cascade] follows a changed key.

          [default 0]
The value when an INSERT leaves the column out: a number, 'text', true, false or now. Several go together: [delete cascade, default 1].

          OwnerId
With Implicit on (top bar), a column named table + Id gets an arrow to that table's PK, even without ->. Diagram only: not a foreign key in the SQL.

          vc
varchar(128). Other types as-is: int, text, date, datetime, decimal(8,2)…

          # e.g. A, B
After a column: the values its sample data takes (Sample data, and the SQL export with it). # t.ex. works too.
